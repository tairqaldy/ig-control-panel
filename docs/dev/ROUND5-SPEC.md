# Round 5 spec — "logs in and it just works": Connect Instagram, out-of-the-box automations, IG analytics, Companion auto-harvest, Ask v2, onboarding, landing v2

Read `docs/dev/HOSTED-SPEC.md` first (tenancy, plans/quotas, 402 shape, cookie, file ownership conventions). This document is the contract for the parallel round-5 work. If something is not specified, pick the simplest option that keeps the OSS single-tenant build working unchanged (owner tenant 1, `HOSTED=false`).

House rules for every agent
- TypeScript strict; `npm run typecheck -w server` / `-w web` must pass before you finish. Do not run `railway`, `git commit`, `git push`, or deploy.
- Server agents: NEVER edit `server/src/db.ts` or `server/src/app.ts`. Add your migration file under `server/src/migrations/00N-*.ts` and register it in `server/src/migrations/index.ts` (one line, keep sorted). Mount routes with one line in `server/src/routes/extra.ts` (`mountPublicExtras` for no-session routes, `mountProtectedExtras` for session routes). Both files are shared: re-read immediately before editing; if an Edit fails because the file changed, re-read and retry.
- Web agents: create your own types in `web/src/lib/types-<feature>.ts` (do not edit `web/src/lib/types.ts`). Shared files `web/src/App.tsx`, `web/src/components/Shell.tsx`, `web/src/lib/store.tsx`, `web/src/styles.css`: additive, minimal edits only (a route line, a nav item, a class), re-read before every edit, retry on conflict. New pages are lazy-loaded (`lazy(() => import(...))`) like Graph/Billing.
- Copy/text: specific, calm, no marketing filler. Never "unlock", "supercharge", "seamless", "leverage", "empower", "journey", "elevate". Say what happens.
- Every metered thing goes through `checkQuota/bumpUsage` (`server/src/services/plans.ts`) and answers 402 via `quotaResponse`.
- Owner env credentials (`META_*`, `IG_*`) keep working for tenant 1 exactly as today when no connected account exists.

## 1. Connect Instagram (OAuth) — `server/src/services/instagram.ts`, `server/src/routes/instagram.ts`, migration 004
Product: "Instagram API with Instagram Login" (Business Login), Graph API v23.0.
- Env: `META_APP_ID`, `META_APP_SECRET`, `META_VERIFY_TOKEN`, `PUBLIC_URL`. `config.ts` may be edited ONLY by adding `metaAppId: process.env.META_APP_ID || ''` (server-instagram agent owns that one edit).
- Table `ig_accounts` (tenant_id INTEGER PRIMARY KEY, ig_user_id TEXT NOT NULL, username TEXT, name TEXT, profile_picture_url TEXT, account_type TEXT, followers_count INTEGER, follows_count INTEGER, media_count INTEGER, access_token_enc TEXT NOT NULL, token_expires_at INTEGER, scopes TEXT, connected_at INTEGER, refreshed_at INTEGER, last_error TEXT, webhook_subscribed INTEGER DEFAULT 0). Encrypt tokens with AES-256-GCM, key = `sha256(config.sessionSecret + ':ig')` (helper `encryptSecret/decryptSecret` in `services/crypto.ts` — server-instagram agent creates it; server-companion agent reuses it, do not duplicate).
- `GET /api/instagram/connect` (protected) → 302 to `https://www.instagram.com/oauth/authorize?client_id=…&redirect_uri=${PUBLIC_URL}/api/instagram/callback&response_type=code&scope=instagram_business_basic,instagram_business_manage_messages,instagram_business_manage_comments,instagram_business_manage_insights&state=<hmac-signed {tid,uid,nonce,exp:+10min}>&force_reauth=false`. If `META_APP_ID` missing → 503 `{error:'Instagram connect is not configured on this server (META_APP_ID/META_APP_SECRET).', code:'not_configured'}`.
- `GET /api/instagram/callback?code&state` (public): verify state; exchange `POST https://api.instagram.com/oauth/access_token` (form: client_id, client_secret, grant_type=authorization_code, redirect_uri, code) → `{access_token,user_id,permissions}`; long-lived: `GET https://graph.instagram.com/access_token?grant_type=ig_exchange_token&client_secret&access_token` → `{access_token, expires_in}`; profile: `GET https://graph.instagram.com/v23.0/me?fields=id,user_id,username,name,account_type,profile_picture_url,followers_count,follows_count,media_count`. Upsert `ig_accounts`; ALSO write settings `ig_user_id` and `ig_access_token` for the tenant so `services/automations.ts` works unchanged; subscribe webhooks `POST https://graph.instagram.com/v23.0/{ig_user_id}/subscribed_apps?subscribed_fields=messages,comments,message_reactions,messaging_postbacks,messaging_seen`; create starter rules (§2). Redirect `302 ${PUBLIC_URL}/automations?connected=1` (or `?error=<short>`).
- `GET /api/instagram/account` (protected) → `{ connected: bool, configured: bool (app id present), account?: {igUserId, username, name, profilePictureUrl, accountType, followersCount, followsCount, mediaCount, connectedAt, tokenExpiresAt, webhookSubscribed}, source: 'oauth'|'env'|null }`. `DELETE /api/instagram/account` → delete row + settings `ig_access_token/ig_user_id` (tenant), best-effort unsubscribe.
- Token refresh: `refreshExpiringTokens()` (`GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token`) for tokens expiring < 10 days; run every 12 h with `setInterval` started from your module init (`startInstagramJobs()` called once from `mountProtectedExtras`).
- Meta callbacks (public): `POST /api/instagram/deauthorize` and `POST /api/instagram/delete` — parse `signed_request` (base64url HMAC-SHA256 with app secret) → `user_id`; deauthorize: disconnect that tenant; delete: disconnect + wipe that tenant's `ig_contacts/automation_events` for that account and respond `{ url: "${PUBLIC_URL}/privacy", confirmation_code: "<uuid>" }`.
- Webhook GET verify / POST already exist at `/api/webhooks/instagram` — do not move them; the routing to a tenant by `ig_user_id` already exists.

## 4. Companion auto-harvest — server: `services/companion.ts`, `routes/companion.ts`, migration 005; extension: `extension/**`; shared core: `harvester/core.js`
Goal: after install, saves sync automatically; the console script remains as fallback for OSS users.
- Table `companion_devices` (id INTEGER PK, tenant_id, name, token_hash TEXT UNIQUE, created_at, last_seen_at, last_harvest_at, last_harvest_count, ua TEXT, server_harvest INTEGER DEFAULT 0, ig_session_enc TEXT NULL, ig_session_status TEXT NULL ('ok'|'invalid'|null), ig_session_checked_at INTEGER NULL); `harvest_runs` (id PK, tenant_id, device_id NULL, source TEXT ('companion'|'server'|'script'|'zip'|'urls'), started_at, finished_at, imported INTEGER, new_items INTEGER, status TEXT, error TEXT).
- Pairing: `POST /api/companion/pair-code` (protected) → `{ code: 'RSF-XXXX-XXXX', expiresAt }` (5 min, single use, stored in meta). `POST /api/companion/pair` (public, body `{code, name, ua}`) → `{ token: 'cmp_<48 hex>', tenantId, appUrl }` (token stored hashed sha256). All device endpoints take `Authorization: Bearer cmp_…`.
- Device endpoints (public router with its own bearer auth middleware): `GET /api/companion/state` → `{ knownIds: [newest 500 ig_pk], total, lastHarvestAt, harvestQuota: {used, limit, resetsAt}, serverHarvest: {enabled, status}, minIntervalMinutes: 360 }`; `POST /api/companion/harvest` body `{ items: HarvestItem[] (same shape the console harvester posts), done: bool, cursor?: string, runId?: number }` → imports through the same code path as `/api/import/harvest` (reuse `services/importers.ts` upsert + `afterImport`), counts ONE `harvests` quota unit per run (first chunk), returns `{ runId, imported, newItems, leftOut, quota }`; `POST /api/companion/session` body `{ sessionid, csrftoken, ds_user_id, ua, enabled: bool }` → opt-in server-side harvesting: store encrypted (§1 crypto helper), `server_harvest=1`; `DELETE /api/companion/session` → wipe. `DELETE /api/companion/devices/:id` (protected) and `GET /api/companion/devices` (protected) → list.
- Server-side harvest job (`startCompanionJobs()` from `mountProtectedExtras`): every 30 min pick tenants with `server_harvest=1 AND ig_session_status != 'invalid'` whose last run > 12 h ago; fetch `https://www.instagram.com/api/v1/feed/saved/posts/?max_id=…` with headers `cookie: sessionid=…; csrftoken=…; ds_user_id=…`, `x-csrftoken`, `x-ig-app-id: 936619743392459`, `x-requested-with: XMLHttpRequest`, the stored `ua`, `referer: https://www.instagram.com/<username>/saved/`; paginate with 1.5–2.5 s jitter, stop when 3 consecutive pages contain only known ids (incremental) or after 40 pages; normalize with `harvester/core.js` (import it — make `core.js` an ESM module usable from Node AND the browser: pure functions `normalizeItem(node, ctx)`, `SAVED_FEED_PATH`, `buildHeaders(...)`), import via the same path; on HTTP 401/403/429 or a login redirect → `ig_session_status='invalid'`, stop, and write a per-tenant notice (meta `companion_notice`) that the web shows ("Instagram signed out the background session — open Companion and reconnect"). Never log cookies. Env `SERVER_HARVEST_ENABLED` (default `true` when hosted, `false` otherwise).
- Extension (`extension/`, Manifest V3, plain JS, no bundler): `manifest.json` (name "Resurfly Companion", permissions `alarms, storage`, optional `cookies`; host_permissions `https://www.instagram.com/*` + `https://resurfly.com/*` + `<all_urls>` NOT allowed — instead the options page lets self-hosters add their app origin and requests it via `chrome.permissions.request`), `background.js` (service worker: alarm every 6 h → `syncNow()`; on install open the popup/onboarding), `popup.html/js` (state: not paired → "Paste the code from Resurfly → Import → Companion" + Connect; paired → last sync, items synced, "Sync now", toggle "Also harvest when my browser is closed" (explains: sends your Instagram session to Resurfly, encrypted; you can revoke any time) which requires the `cookies` permission and posts to `/api/companion/session`), `options.html` (app URL, remove pairing), `lib/core.js` (copy of `harvester/core.js` kept in sync — the build step is a plain `cp`; document it), icons (reuse `web/public/favicon.svg` rendered to PNG 16/48/128 — generate with `sharp` in a tiny `extension/build-icons.mjs` script). Sync algorithm: `GET /state` → paginate saved feed via `fetch` with `credentials:'include'` (works because the extension has the host permission and the user is logged in) → chunk POST 100 items → stop rule as above → badge text = new items count for 24 h. Handle "not logged in" (Instagram returns HTML/redirect) → notify via badge "!" and popup message. Full first run: no stop rule, resumable cursor in `chrome.storage.local`.
- Docs `docs/COMPANION.md`: install (Chrome Web Store link placeholder + "Load unpacked" for OSS), pairing, what it sends, the opt-in, self-host origins.
- Web (web-instagram agent): Import page becomes: **1. Companion (recommended)** — install button (CWS link placeholder `https://chrome.google.com/webstore/detail/resurfly-companion/…` env `VITE_COMPANION_URL` fallback to `docs/COMPANION.md`), "Get pairing code" → shows code + expiry, device list with last sync, opt-in status; **2. One-time script** (existing bookmarklet/console flow, collapsed by default); **3. Advanced** (Instagram data-export ZIP, paste URLs, collapsed). Analysis plan panel stays.
